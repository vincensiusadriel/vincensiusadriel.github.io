How to Deploy a Private Hugo Site to GitHub Pages

2026-10-09
|
7 min read
|
#hugo #github-pages #github-actions #deployment

GitHub Pages can serve a public site without making its source repository public. A GitHub Actions workflow in the private repository builds the Hugo site, then pushes only the generated public/ directory to a separate public repository.

This guide publishes the private vincensiusadriel/portfolio repository to the public vincensiusadriel/vincensiusadriel.github.io repository. The resulting site is available at https://vincensiusadriel.github.io/.

The deployment has three parts:

private Hugo repository
        |
        | GitHub Actions builds the site
        v
public vincensiusadriel.github.io repository
        |
        | GitHub Pages publishes main
        v
https://vincensiusadriel.github.io/

The source content, templates, configuration, and history remain private. The generated HTML, CSS, JavaScript, images, and other files required by the site are public.

Prerequisites

Before starting, make sure you have:

  • A Hugo site in a private GitHub repository.
  • Permission to manage Actions secrets in the private repository.
  • Permission to create and configure the public publishing repository.
  • A production build that works locally.
  • Git, Hugo Extended, Go, Node.js, and npm when required by the theme.

This portfolio uses the nerdy theme as the themes/nerdy Git submodule. Its Tailwind CSS pipeline requires npm dependencies and a two-pass Hugo build.

Set the production URL

A GitHub user site must use a public repository named exactly <username>.github.io. Set the Hugo baseURL to the corresponding root URL, including the trailing slash:

baseURL: "https://vincensiusadriel.github.io/"

This is different from a project site URL such as https://vincensiusadriel.github.io/portfolio/. Using the old project path would generate incorrect canonical URLs and asset links after moving the site to the domain root.

Create the public repository

Create a public GitHub repository named:

vincensiusadriel/vincensiusadriel.github.io

Keep this repository dedicated to generated output. It does not need a README, license, or .gitignore; the deployment workflow creates and replaces its main branch.

Do not add source content or secrets to this repository. Everything committed to it can be read by anyone.

Create a deployment key

The private repository’s GITHUB_TOKEN is scoped to that repository and cannot push to a different repository. Use a dedicated SSH deploy key that grants write access only to the public publishing repository.

Generate an Ed25519 key pair outside the project directory:

ssh-keygen -t ed25519 \
  -C "portfolio GitHub Pages deployment" \
  -f "$HOME/.ssh/portfolio-pages-deploy" \
  -N ""

This creates:

  • $HOME/.ssh/portfolio-pages-deploy: the private key.
  • $HOME/.ssh/portfolio-pages-deploy.pub: the public key.

Never commit either key to the source or publishing repository.

Add the public key to the publishing repository

Open vincensiusadriel/vincensiusadriel.github.io on GitHub, then:

  1. Select Settings.
  2. Select Deploy keys under Security.
  3. Select Add deploy key.
  4. Enter portfolio-pages as the title.
  5. Use the contents of $HOME/.ssh/portfolio-pages-deploy.pub as the key.
  6. Enable Allow write access.
  7. Select Add key.

The key can now push to this repository, but it cannot access other repositories in the account.

Add the private key to the source repository

Open the private vincensiusadriel/portfolio repository on GitHub, then:

  1. Select Settings.
  2. Select Secrets and variables, then Actions.
  3. Select New repository secret.
  4. Set the name to ACTIONS_DEPLOY_KEY.
  5. Use the complete contents of $HOME/.ssh/portfolio-pages-deploy as the secret value, including the BEGIN and END lines.
  6. Select Add secret.

GitHub masks the secret in workflow logs. The workflow passes it only to the publishing action.

Add the publishing workflow

Create .github/workflows/pages.yml in the private source repository:

name: Publish Hugo site

on:
  push:
    branches:
      - master
  workflow_dispatch:

permissions:
  contents: read

concurrency:
  group: publish-site
  cancel-in-progress: false

jobs:
  publish:
    runs-on: ubuntu-latest

    steps:
      - name: Check out repository
        uses: actions/checkout@v4
        with:
          submodules: recursive

      - name: Set up Go
        uses: actions/setup-go@v5
        with:
          go-version-file: themes/nerdy/go.mod

      - name: Set up Hugo
        uses: peaceiris/actions-hugo@v3
        with:
          hugo-version: "0.167.0"
          extended: true

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: npm

      - name: Generate Hugo npm workspace
        run: hugo mod npm pack

      - name: Install npm dependencies
        run: npm ci

      - name: Build site
        env:
          HUGO_ENVIRONMENT: production
        run: |
          export PATH="$PWD/node_modules/.bin:$PATH"
          hugo --renderToMemory
          hugo --gc --minify --cleanDestinationDir

      - name: Publish generated site
        uses: peaceiris/actions-gh-pages@84c30a85c19949d7eee79c4ff27748b70285e453 # v4.1.0
        with:
          deploy_key: ${{ secrets.ACTIONS_DEPLOY_KEY }}
          external_repository: vincensiusadriel/vincensiusadriel.github.io
          publish_branch: main
          publish_dir: ./public
          force_orphan: true
          full_commit_message: Publish generated site
          user_name: github-actions[bot]
          user_email: 41898282+github-actions[bot]@users.noreply.github.com

If the source repository uses main as its default branch, replace master in the workflow trigger.

The workflow performs these tasks:

  1. Checks out the private source and its theme submodule.
  2. Installs the Go, Hugo Extended, and Node.js versions required by the site.
  3. Generates the ignored packages/hugoautogen npm workspace.
  4. Installs locked npm dependencies with npm ci.
  5. Runs Hugo in memory to generate hugo_stats.json for Tailwind CSS.
  6. Runs the minified production build and writes it to public/.
  7. Pushes only public/ to the public repository’s main branch.

The publishing action is pinned to the commit for version 4.1.0 because it receives the private deployment key. Review and deliberately update the pinned commit when upgrading the action.

force_orphan: true keeps only the latest generated snapshot in the public branch. This prevents removed pages from remaining available in Git history. full_commit_message also prevents a private source commit message or commit hash from appearing in the public repository.

Run the first deployment

Commit and push the workflow to master, or run it manually:

  1. Open the private repository on GitHub.
  2. Select Actions.
  3. Select Publish Hugo site.
  4. Select Run workflow.
  5. Wait for the publish job to finish.

The first successful run creates the main branch in vincensiusadriel/vincensiusadriel.github.io and commits the generated site.

Enable GitHub Pages

After the first deployment creates main, configure the public repository:

  1. Open vincensiusadriel/vincensiusadriel.github.io on GitHub.
  2. Select Settings.
  3. Select Pages under Code and automation.
  4. Set Source to Deploy from a branch.
  5. Select the main branch and /(root) folder.
  6. Select Save.

Wait for GitHub Pages to finish publishing, then open:

https://vincensiusadriel.github.io/

Every later push to master builds and publishes a new snapshot. A workflow dispatch can publish the current source again without creating a new commit in the private repository.

Test the production build locally

Run the same essential build steps before pushing:

git submodule update --init --recursive
hugo mod npm pack
npm ci
export PATH="$PWD/node_modules/.bin:$PATH"
export HUGO_ENVIRONMENT=production
hugo --renderToMemory
hugo --gc --minify --cleanDestinationDir

Serve the generated directory to inspect it in a browser:

python3 -m http.server 8080 --directory public

Then open http://localhost:8080/. Check links, images, styles, scripts, canonical URLs, and the sitemap before publishing.

The deployment command intentionally omits --buildDrafts. Content with draft: true remains available during local development but is excluded from the public site.

Protect private information

Keeping the source repository private does not make generated content private. Before deploying, review anything Hugo can copy or render, including:

  • Published Markdown content and front matter.
  • Files under static/ and other mounted static directories.
  • Images and downloadable documents.
  • Data files used by templates.
  • Values embedded into generated JavaScript, HTML, or source maps.

Do not pass credentials to Hugo or store them in content. Repository secrets should be used only by the workflow steps that need them.

The generated repository is disposable output. Do not edit it manually because the next deployment replaces its branch. Keep all authored content and configuration in the private source repository.

Rotate or revoke the deployment key

If the private key is exposed, remove its deploy key from the public repository immediately. Generate a new key pair, add the new public key with write access, and replace the ACTIONS_DEPLOY_KEY secret in the private repository.

Deleting the Actions secret stops future deployments but does not revoke a key that has been copied elsewhere. Remove the deploy key from the public repository to revoke it completely.

Troubleshooting

The workflow reports Permission denied (publickey)

Confirm that ACTIONS_DEPLOY_KEY contains the complete private key and that the matching public key is attached to the publishing repository with Allow write access enabled. Preserve all key line breaks when creating the secret.

The workflow reports Repository not found

Confirm that external_repository exactly matches the public repository owner and name:

external_repository: vincensiusadriel/vincensiusadriel.github.io

Also confirm that the public repository already exists. The workflow creates the publishing branch, not the repository itself.

The workflow cannot check out the theme

Confirm that .gitmodules uses an accessible HTTPS URL and that the checkout step includes submodules: recursive. A private theme repository requires separate credentials with access to both private repositories.

The page loads without styling

Confirm that npm ci succeeds, node_modules/.bin is on PATH, and both Hugo passes run. The first pass generates the build statistics Tailwind needs to discover classes used by Hugo templates.

Also verify that baseURL points to the domain root:

baseURL: "https://vincensiusadriel.github.io/"

GitHub Pages returns 404

Check that the public repository contains generated files on main. In its Pages settings, confirm that the source is Deploy from a branch with main and /(root) selected. The first publication can take a few minutes.

A deployment does not create a new public commit

The publishing action skips a commit when the generated output has not changed. This is expected and does not indicate a failed deployment.

A draft post is missing

Drafts are intentionally excluded from production. Remove draft: true, or change it to draft: false, then commit and push the source again.
